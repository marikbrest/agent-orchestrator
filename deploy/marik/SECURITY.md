# Threat model and findings

Trust boundaries are the operator, the Docker host, each worker container, the repository under test, the provider, GitHub and the remote mobile client. Repository files, issue content, dependencies and agent-produced patches are untrusted. Docker operators control all volumes and containers. Each daemon and the tasks it starts share the same worker identity.

| Severity | Finding and evidence | Exploit and impact | Mitigation, status and verification |
| --- | --- | --- | --- |
| High | Codex account selection is daemon-global. See `codex_account_switch_coordinator.go` and open upstream issue #5947 for a reported provider-switch credential-routing fault. | A session and an account switch can overlap in one daemon. Routing credentials to an unexpected provider can disclose them. | Avoid switching accounts in the pilot. The fixture separates homes. Verify concurrently with synthetic account markers first, then with authorized accounts and an endpoint allowlist. The upstream report was not reproduced. |
| High | The loopback router in `backend/internal/httpd/router.go` trusts local reachability for general control, while the LAN listener has separate authentication. | Publishing the control API could allow an unauthorized party to manipulate sessions or access terminal capabilities. Code inside a worker can reach its own daemon. | No published ports or external network in the fixture. Exercise the upstream LAN tunnel unauthorized-client tests. A connected pilot must test unauthenticated and revoked clients across REST, WebSocket and tunnel routes. |
| High | Drivers launch executables with workspace access and inherit worker context. | A malicious prompt, repository hook or dependency may trigger commands, read that worker's credentials and tamper with output. A kernel vulnerability could cross container boundaries. | Separate homes and repositories, read-only root, no host mounts or socket, non-root and network none in the fixture. Test with synthetic secrets before provider enrollment. For hostile code, use separate VMs and credential-free execution sandboxes where practical. |
| High | Bootstrap scripts invoke sudo, change login linger, and download release or branch-selected installers and packages. | A compromised update can run code in the service account or with host privileges. | No bootstrap execution in this lab. Base images pinned by digest. Before production, pin and verify provider artifacts, snapshot OS repositories, validate provenance, and rehearse upgrade and rollback offline. |
| Medium | Pairing secrets and session streams can grant remote control. Upstream documents a plaintext LAN endpoint and an alternate tunnel path. | A stolen password, QR or logs could permit access. Listener reachability expands impact. | Private VPN and restricted ACLs, pairing secret rotation, and device revocation for the pilot. Test old credentials and reconnect after daemon restart. Physical validation pending. |
| Medium | AO state, transcripts, runtime logs and backups may contain sensitive data. | Anyone with Docker access or a volume backup could recover prompts or credentials. | Remote telemetry disabled in the lab. Control retention and encrypt archives. Search synthetic canaries in logs and backups before live enrollment. |
| Medium | npm, Go, image and OS dependencies have distinct update and vulnerability surfaces. | A compromised build or runtime dependency could inject code. | Go checksums and image digests in use. CI builds and scans the lab image and manifests. Require clean reviewed scans and remediation decisions before a release. |
| Medium | Git remotes, hooks and credential helpers inherit the publisher's access. | An injected instruction may push or overwrite branches if a write token is available. | Keep write credentials out of workers. Review and apply patches in a separate publisher, require branch protection and human PR review, and test rejection of direct pushes before connected operation. |

Production status is blocked on verified live account isolation, least-privilege publishing, reviewed network controls, image and dependency findings, task scheduling and physical-device acceptance. A smoke pass establishes container and filesystem separation only.

## Scanner evidence

- **Critical candidate, upstream npm dependencies.** Trivy 0.76.2 flagged CVE-2026-102422 in shell-quote 1.10.0. It reports command execution via crafted shell input and lists 1.11.0 as fixed. Reachability needs call-site review. The Go-only lab image does not install the npm dependencies. Upgrade the affected lockfile on a dedicated branch, retest untrusted input paths and rerun the scan.
- **High, lab image dependencies.** Trivy reported 103 high-severity Debian findings and four high-severity Go binary findings. One Go finding is CVE-2026-111943, a certificate-validation issue for which the scanner lists Go 1.27.3 as a fixed release in the current minor series. The image is scoped to an offline test. Refresh pinned inputs and rescan before enabling connectivity.
- **High pending triage, upstream history.** Redacted Gitleaks 8.30.1 scanned 18,133 commits and reported 149 matches. A match alone does not establish an active credential. Restrict access to detailed reports, validate via the owning maintainers and revoke confirmed credentials. The staged lab diff produced zero matches. Preserve upstream history as requested.
